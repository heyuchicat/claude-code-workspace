# Outlook IMAP アカウント設定方法

「IMAP アカウントの設定」画面（受信メール／送信メールのサーバー名とポートを入力する画面）の入力手順です。

---

## 1. 今表示されている画面について

この画面は、Outlook がメールアドレスから設定を自動検出できなかったときに表示されます。
サーバー名が空欄で、ポートに初期値（受信 `143` / 送信 `25`）、暗号化方法が「なし」になっているのがその状態です。

> **重要:** 初期値のまま「次へ」を押さないでください。
> ポート 143 / 25 で「暗号化方法: なし」は、**ID とパスワードが暗号化されずにネットワークを流れます。**
> 多くの企業サーバーやプロバイダーはこの接続を拒否するため、そもそも接続に失敗します。
> 下記の暗号化ありの設定に変更してください。

---

## 2. 入力する値

### 推奨（暗号化あり）

| 項目 | 受信メール (IMAP) | 送信メール (SMTP) |
|---|---|---|
| サーバー | `imap.（自社ドメイン）` など ※要確認 | `smtp.（自社ドメイン）` など ※要確認 |
| ポート | **993** | **587** |
| 暗号化方法 | **SSL/TLS** | **STARTTLS** |
| SPA でのログオンが必要 | チェックしない | チェックしない |

送信側で 587 / STARTTLS が通らない場合は、代替として **465 / SSL-TLS** を試してください。

### 参考: ポートと暗号化方法の対応

| 用途 | ポート | 暗号化方法 | 備考 |
|---|---|---|---|
| IMAP | 993 | SSL/TLS | 推奨 |
| IMAP | 143 | STARTTLS | サーバーが 993 非対応の場合 |
| IMAP | 143 | なし | 非推奨（平文） |
| SMTP | 587 | STARTTLS | 推奨（サブミッションポート） |
| SMTP | 465 | SSL/TLS | 587 が使えない場合 |
| SMTP | 25 | なし | 非推奨。ISP 側でブロックされることが多い |

## 3. サーバー名（ホスト名）の確認方法

サーバー名は組織ごとに異なるため、**推測で入力しないでください。**
以下のいずれかの方法で正しい値を入手します。

1. **社内のシステム管理者／情報システム部門に問い合わせる（最も確実）**
   「IMAP の受信・送信サーバー名、ポート、暗号化方式、認証方式」を聞いてください。

2. **メールサービス提供元のマニュアルを確認する**
   レンタルサーバーやプロバイダーの「メールソフト設定」ページに記載されています。

3. **すでに設定済みの端末からコピーする**
   同じアカウントが動いている PC / スマートフォンがあれば、そのメールアプリの
   アカウント設定画面にサーバー名が表示されています。
   - Outlook (Windows): `ファイル` → `アカウント設定` → 対象アカウントを選択 → `変更`
   - iPhone: `設定` → `アプリ` → `メール` → `メールアカウント` → 対象アカウント → `アカウント`

4. **Microsoft 365 / Exchange Online を利用している場合**
   IMAP ではなく **Exchange (Microsoft 365) として追加する**のが正しい手順です（下記 5 章）。
   どうしても IMAP を使う場合の値は次のとおりです。

   | 項目 | 値 |
   |---|---|
   | 受信サーバー | `outlook.office365.com` / 993 / SSL-TLS |
   | 送信サーバー | `smtp.office365.com` / 587 / STARTTLS |

   ※ Microsoft 365 では基本認証が既定で無効化されているため、IMAP 接続には
   テナント側で OAuth2（先進認証）または IMAP の有効化が必要です。管理者に確認してください。

---

## 4. 設定手順

1. 「受信メール」の **サーバー** に、確認したホスト名を入力する。
2. **ポート** を `993` に変更する。
3. **暗号化方法** を `SSL/TLS` に変更する。
4. 「セキュリティで保護されたパスワード認証 (SPA) でのログオンが必要」は**チェックしない**。
   （SPA = NTLM 認証。管理者から指示があった場合のみチェックします。）
5. 「送信メール」の **サーバー** に、確認したホスト名を入力する。
6. **ポート** を `587`、**暗号化方法** を `STARTTLS` に変更する。
7. 「次へ」をクリックする。
8. パスワード入力画面が出たらメールアカウントのパスワードを入力し、「接続」をクリックする。
9. 「アカウントが正常に追加されました」と表示されたら完了。

### 追加後に確認すること（送信認証）

送信時のみエラーになる場合は、送信サーバーの認証設定を確認します。

`ファイル` → `アカウント設定` → `アカウント設定` → 対象アカウント → `変更`
→ `詳細設定` → `送信サーバー` タブ
→ **「送信サーバー (SMTP) は認証が必要」にチェック** →
**「受信メール サーバーと同じ設定を使用する」を選択**

---

## 5. Microsoft 365 / Exchange の場合（推奨手順）

勤務先が Microsoft 365 を使っている場合は、IMAP ではなく Exchange 接続を使ってください。
予定表・連絡先・タスクの同期、および先進認証（多要素認証）に対応します。

1. Outlook を閉じる。
2. `コントロール パネル` → `Mail`（32bit）→ `電子メール アカウント` → `新規`
3. 「電子メール アカウント」を選び、名前・メールアドレス・パスワードを入力して `次へ`
   （自動検出に任せる。手動設定画面が出た場合は `Office 365` / `Exchange` を選択）
4. サインイン画面が出たら会社アカウントで認証する。

この画面（IMAP アカウントの設定）が出てしまった場合は、左下の **「前に戻る」** から
アカウントの種類の選択画面に戻り、`Office 365` または `Exchange` を選び直してください。

## 6. よくあるエラーと対処

| 症状 | 想定される原因 | 対処 |
|---|---|---|
| 「サーバーへの接続に失敗しました」 | サーバー名の誤り、ポート／暗号化の不一致 | ホスト名のスペルを確認。993/SSL-TLS ⇔ 143/STARTTLS を入れ替えて試す |
| 「ユーザー名またはパスワードが正しくありません」が繰り返し出る | ユーザー名の形式違い、または多要素認証 | ユーザー名をメールアドレス全体（例: `user@example.co.jp`）で試す。別形式（`ドメイン\ユーザー名`）を指定されている場合は管理者の指示に従う。MFA 有効なら**アプリ パスワード**が必要 |
| 受信はできるが送信できない | SMTP 認証が未設定、または ISP がポート 25 をブロック | 4 章「送信認証」の設定を実施。ポートを 587（または 465）に変更 |
| 証明書の警告が出る | サーバー名が証明書と不一致 | 証明書に記載された正式なホスト名を管理者に確認して入力（警告は無視しない） |
| タイムアウトする | ファイアウォール／セキュリティ ソフトが 993・587 を遮断 | ネットワーク管理者に該当ポートの許可を依頼 |
| Microsoft 365 で認証が通らない | 基本認証が無効化されている | Exchange として追加する（5 章）、または管理者に OAuth2 の有効化を依頼 |
