# エックスサーバー — 初期セットアップ（REXEL公開前の下準備）

対象: エックスサーバーを契約したばかりで中身が空、独自ドメイン（お名前.com取得）は
あるがまだ接続していない状態。

サーバーパネルの項目名は時期により多少変わることがあります。
表記が違う場合は近い名前のメニューを探してください。

## 今回の進め方

**独自ドメインの接続は後回しにします。** かわりにエックスサーバーが契約時に
無料で割り当ててくれる **「初期ドメイン」**（`◯◯◯◯.xsrv.jp` という形式のURL）を
使います。これは契約した瞬間からこのサーバーに向いているため、DNSの設定を
一切待たずに、今すぐ WordPress のインストールと REXEL の移管作業を進められます。

- **フェーズ1**（このガイドの1〜5章）: 初期ドメインで WordPress を動かし、
  REXEL の内容をインポートする。**今日はここまで。**
- **フェーズ2**（6〜9章）: お名前.com のドメインが使える状態になったら、
  それをこのサイトに接続する。**準備ができたときに改めて進めてください。**

# フェーズ1 — 初期ドメインでWordPressを動かす（今すぐ）

## 1. 初期ドメインを確認する

1. **サーバーパネル**にログイン
   （エックスサーバーの契約完了メールに記載の「サーバーパネル」URL、
   もしくは https://www.xserver.ne.jp/login/ から）
2. 「サーバー情報」を開く
3. 「初期ドメイン」という項目に `◯◯◯◯.xsrv.jp` の形式のURLが表示されているので
   メモしておく（この後何度も使います）

このURLはドメインを何も設定しなくても、契約した時点で既にこのサーバーに
向いています。独自ドメインが無くても、これだけでサイトを公開・確認できます。

## 2. WordPress をインストールする

1. サーバーパネル →「WordPress」→「WordPress簡単インストール」
2. 対象の「ドメイン」で、1章でメモした初期ドメイン（`◯◯◯◯.xsrv.jp`）を選択
   （独自ドメインはまだ追加していないので一覧には出ません。これで正常です）
3. 「WordPress簡単インストール」タブで以下を入力
   - **サイトURL**: 空欄のまま（ドメイン直下に入れる場合）
   - **ブログ名**: 後で変更可能なので仮の名前でよい（例: REXEL）
   - **ユーザー名 / パスワード**: 本番管理者用の新しいものを設定
     （Studio側と同じものを使い回さない方が安全です）
   - **メールアドレス**: 通知を受け取りたいアドレス
   - **テーマ**（デフォルトテーマ / Cocoon / Lightning などの選択肢）:
     **どれを選んでも構いません。** これはXserverが最初から用意している
     おまけのテーマ一覧で、REXELのような独自テーマはここには出てきません。
     4章でStudioの内容をインポートするか、`外観 → テーマ → 新規追加 →
     テーマのアップロード` でREXELの zip を入れると、ここで選んだテーマは
     自動的に置き換わります。迷ったら「デフォルトテーマ」のままでOKです。
4. 「インストール（確認）」→「インストール（確定）」

完了すると管理画面URL（`https://◯◯◯◯.xsrv.jp/wp-admin/`）が表示されます。
**このURLとログイン情報は、この後インポートすると一時的に使えなくなります**
（`MIGRATION-GUIDE.md` の「A-4」参照）。念のため控えておいてください。

> 初期ドメインは基本的に最初から `https://` に対応しています。
> `https://◯◯◯◯.xsrv.jp/` を開いて鍵マークが出ない場合のみ、
> サーバーパネル →「SSL設定」→ 対象ドメインで「独立SSL設定」を追加してください
> （フェーズ2の7章と同じ操作です）。

## 3. アップロード容量の上限を上げておく（推奨）

`MIGRATION-GUIDE.md` のルートA（All-in-One WP Migration）でインポートする際、
PHPの初期設定だと容量オーバーになることがあります。先に上げておくと手戻りがありません。

1. サーバーパネル →「PHP Ver.切替」で PHP のバージョンを確認
   （最新の安定版を推奨。WordPressの推奨PHPバージョンに合わせる）
2. サーバーパネル →「php.ini設定」
3. 対象ドメイン（初期ドメイン）を選び、以下を編集
   ```
   upload_max_filesize = 512M
   post_max_size = 512M
   memory_limit = 256M
   max_execution_time = 300
   ```
4. 「確認画面へ進む」→保存

## 4. Studio の内容をインポートする

ここから `MIGRATION-GUIDE.md` の**フェーズ2・ルートA**（All-in-One WP Migration）に
従って、Studio側からエクスポートした `.wpress` ファイルをこの本番サイトに
インポートしてください。

**1点だけ、このガイドと異なる箇所があります。**
`MIGRATION-GUIDE.md` の「5. よくあるトラブル」→「画像の URL に `localhost` が
残っている」の項目で、通常は本番の独自ドメインに向けて置換しますが、
**今回はまだ独自ドメインが無いため、置換後の文字列は初期ドメインにしてください。**

```
検索する文字列   : http://localhost:8881（Studio側のサイトURL）
置換後の文字列   : https://◯◯◯◯.xsrv.jp（1章でメモした初期ドメイン）
```

独自ドメインへの向け先変更は、フェーズ2の8章でまとめて行います。
（つまりURLの置換は今回と、独自ドメイン接続時の計2回行うことになります）

インポート後にログイン情報がStudio側のものへ置き換わる点は、
`MIGRATION-GUIDE.md` の「A-4. インポート直後の必須作業」の通りです。

## 5. フェーズ1のここまで確認

- [ ] `https://◯◯◯◯.xsrv.jp/` で鍵マーク付きで開ける
- [ ] トップページ・下層ページにREXELの内容（画像・文言・フォント）が表示される
- [ ] `https://◯◯◯◯.xsrv.jp/wp-admin/` でログインできる
- [ ] `MIGRATION-GUIDE.md` の「フェーズ3 — 移管後の確認」の項目を一通り確認した

ここまで確認できれば、REXELの移管作業そのものは完了です。
独自ドメインを世間に公開するのは、お名前.com側の準備が整ってからで大丈夫です。

# フェーズ2 — 独自ドメインを接続する（準備ができたら）

前回相談した内容の通り、このドメインの独自メールアドレスは
**Google Workspace** で運用中とのことなので、ネームサーバーは
**お名前.com のまま変更せず**、「A レコード」という1行の設定だけを
エックスサーバー宛に追加します。この方法なら Google Workspace の
メール設定（MX・SPF・DKIM）に一切触れないため、メールが止まるリスクがありません。

> ネームサーバーを丸ごとエックスサーバーに切り替える方法（多くのXserver解説記事が
> 紹介している方法）も存在しますが、その場合は Google Workspace 用の MX/SPF/DKIM
> レコードをエックスサーバー側で一から再設定しないと**切り替えた瞬間から
> 会社のメールが届かなくなります**。今回はメールを止めない方法を優先します。

## 6. ドメインをサーバーに追加してAレコードを向ける

### 6-1. エックスサーバー側にドメインを追加する

1. サーバーパネル →「ドメイン」→「ドメイン設定」
2. 「ドメイン設定追加」タブを選び、お持ちのドメイン名を入力して追加
3. 「無料independent SSLを利用する（自動更新）」にチェックを入れて追加
   （後述のSSL設定が自動で進みます。項目が無ければ手動で7章を行う）
4. 追加後、「ドメイン」→「サーバー情報」（または追加したドメインの詳細画面）で
   **「IPアドレス」** を確認してメモしておく（例: `xxx.xxx.xxx.xxx`）
   ← これが次の手順で使う「向き先」です

### 6-2. お名前.com 側で A レコードだけをエックスサーバーに向ける

1. [お名前.com Navi](https://navi.onamae.com/) にログイン
   （お名前.com の会員ID・パスワード。ドメイン取得時の登録メールに記載があります）
2. 上部メニュー「ドメイン」→「DNS関連機能設定」を開く
3. 対象のドメイン名にチェックを入れ、「DNSレコード設定を利用する」の「設定する」を選ぶ
4. 「入力画面へ」→ 以下の内容で **追加**（既存の MX・TXT 等の行は**触らない**）
   ```
   ホスト名   : （空欄のまま。ドメイン直下を示します）
   TYPE       : A
   TTL        : 3600（初期値のままでよい）
   VALUE      : 6-1でメモしたエックスサーバーのIPアドレス
   ```
5. `www.ドメイン名` でもアクセスできるようにしたい場合は、もう1行追加
   ```
   ホスト名   : www
   TYPE       : A
   VALUE      : 同じIPアドレス
   ```
6. 「確認画面へ進む」→「追加」→「設定する」

> **既存の行（MX・TXT・CNAME など）は絶対に削除・変更しないでください。**
> ここに Google Workspace のメール配送設定（MXレコード）や送信ドメイン認証
> （SPF/DKIMのTXTレコード）が入っています。追加するのは A レコード1〜2行のみです。

反映まで数十分〜数時間程度です。反映状況は次のコマンドで確認できます（ターミナルで）。

```bash
dig ドメイン名 A +short
```

6-1でメモしたエックスサーバーのIPアドレスが表示されれば反映済みです。
念のためメールも生きているか確認する場合は次のコマンドを使います。

```bash
dig ドメイン名 MX +short
```

Google Workspace のメールサーバー（`aspmx.l.google.com` などを含む行）が
今まで通り表示されていれば、メール設定は変わっていません。

## 7. 独立SSL（https化）を設定する

6-1の手順3でチェックを入れていれば自動で設定されるので、この章は
反映されているか確認するだけで済みます。反映されていない場合のみ手動で行います。

1. サーバーパネル →「SSL設定」
2. 対象ドメイン（独自ドメインの方）を選択し「独立SSL設定」タブ
3. 「独立SSL設定を追加する」→ 反映まで最大1時間程度

反映後、`https://独自ドメイン/` でブラウザに鍵マークが出ることを確認してください。

> A レコードがまだエックスサーバーに向いていない段階ではSSLの発行が
> 保留になることがあります。6章の `dig ドメイン名 A +short` の反映を
> 待ってから再確認してください。

## 8. URLを初期ドメインから独自ドメインへ置換する

フェーズ1でインポートした際、サイトの中のURLは初期ドメイン
（`https://◯◯◯◯.xsrv.jp`）を向いた状態になっています。独自ドメインに
向け直す必要があります。

1. `https://◯◯◯◯.xsrv.jp/wp-admin/` にログイン（まだ初期ドメインの方でログイン）
2. 「プラグイン → 新規追加」で **Better Search Replace** を検索してインストール、有効化
3. 「ツール → Better Search Replace」を開く
4. 以下を入力
   ```
   検索する文字列    : https://◯◯◯◯.xsrv.jp
   置換後の文字列    : https://独自ドメイン
   対象テーブル      : すべて選択
   ```
5. 一番下のチェックボックス（Dry Run / ドライラン）を**入れたまま**一度実行し、
   何件ヒットするか確認する
6. 件数を確認できたら、チェックを外して本実行する
7. 「設定 → 一般」を開き、「WordPress アドレス (URL)」と「サイトアドレス (URL)」が
   独自ドメイン（`https://` 付き）になっているか確認。なっていなければ手動で修正して保存
8. 「設定 → パーマリンク」を開き、何も変更せず「変更を保存」を **2 回** クリック
9. ブラウザのキャッシュを消してから `https://独自ドメイン/` を開き直して確認

初期ドメイン（`https://◯◯◯◯.xsrv.jp/`）の方は、その後もそのままアクセスできる
状態が残ります。実害はありませんが、検索エンジンに同じ内容が2つのURLで
見えるのが気になる場合は、サーバーパネルの「ドメイン設定」から初期ドメインでの
公開を制限する設定（表記はバージョンにより異なります）を使ってください。
必須ではないので、気にならなければそのままで問題ありません。

## 9. フェーズ2のここまで確認

- [ ] `dig ドメイン名 A +short` でエックスサーバーのIPアドレスが表示される
- [ ] `dig ドメイン名 MX +short` で Google Workspace のメールサーバーが
      今まで通り表示される（＝メール設定は無事）
- [ ] `https://独自ドメイン/` で鍵マーク付きで開ける
- [ ] `https://独自ドメイン/wp-admin/` でログインできる
- [ ] サイト内のリンク・画像URLが独自ドメインになっている（右クリックで確認）
- [ ] `設定 → 表示設定` で「検索エンジンがサイトをインデックスしないようにする」の
      チェックが外れている

## トラブル

### ドメインを追加したのに「このドメインは使用できません」と出る

他のサーバーやサービスに紐付いたままの可能性があります。
取得元のサービス側で、そのドメインが別のホスティングに使われていないか確認してください。

### SSLが「発行失敗」になる

ほとんどの場合、A レコードの反映待ちです。6章の `dig ドメイン名 A +short` で
エックスサーバーのIPアドレスが表示されることを確認してから、サーバーパネルで
「独立SSL設定」を一度削除して入れ直すと直ることが多いです。

### WordPress簡単インストールでエラーになる

同じドメインに既にWordPressが入っていないか確認してください。
契約直後であれば通常は発生しません。

### お名前.comの「DNSレコード設定」で行を追加できない / 既存のMXレコードが見当たらない

「DNS関連機能設定」の一覧に対象ドメインが出ない場合、ドメインが
「ムームーDNS」など別のDNSサービスに向いている可能性があります。
その場合はそのサービス側の管理画面でAレコードを追加してください。
既存のMX/TXTレコードが見当たらない、または触ってしまって不安なときは、
**変更を確定する前に**お名前.comのサポートに問い合わせて現状を確認するのが安全です。
Google Workspace 側の「管理コンソール → アカウント → ドメイン」からも
現在期待されているMX/SPF/DKIMの値を確認できます。

### A レコードを追加したのに `dig` で反映が確認できない

- ホスト名が空欄（ドメイン直下）になっているか再確認（`www` などを
  誤って入れていないか）
- 既存の A レコードが残っていて競合していないか（お名前.comの初期設定で
  ドメインが別のIPを指す A レコードを持っている場合、それを新しい値に
  書き換える必要があります。行を増やすのではなく既存行を編集します）
- キャッシュの影響で自分の回線からは反映が遅く見えることがあります。
  `dig @8.8.8.8 ドメイン名 A +short` のように別のDNSサーバーを指定して
  確認すると早く反映が見えることがあります

### 独自ドメインに接続したのに画像やCSSが崩れる

8章のURL置換がまだ済んでいないか、キャッシュが残っています。
Better Search Replace を実行したか確認し、ブラウザのキャッシュを消してから
再確認してください。エックスサーバー側にキャッシュ機能を有効にしている場合は
サーバーパネルの「サーバーキャッシュ設定」でキャッシュもクリアしてください。
