# REXEL — WordPress Studio から本番サーバーへの移管ガイド

対象環境: WordPress Studio（ローカル） → エックスサーバー

> **本番のエックスサーバーがまだ空（契約したばかり）の場合**は、先に
> [`XSERVER-SETUP.md`](./XSERVER-SETUP.md) のフェーズ1（初期ドメインでの
> WordPressインストール）を済ませてから、このガイドのフェーズ2に進んでください。
> 独自ドメインの接続はドメイン側の準備が整ってから（`XSERVER-SETUP.md` の
> フェーズ2）で構いません。

---

## 0. 最初に知っておくこと

### テーマの zip だけでは移管は完了しません

これが一番重要です。REXEL の変更内容は、**2 か所に分かれて保存されています**。

| 変更した場所 | 保存先 | テーマ zip に入るか |
|---|---|---|
| エディタで `style.css` / `functions.php` / テンプレートファイルを直接編集 | テーマフォルダ内のファイル | **入る** |
| 管理画面の「外観 → エディター」（サイトエディター）で編集 | データベース (`wp_template` 等) | **入らない** |
| ブロックエディタで固定ページ・投稿の文言や画像を編集 | データベース (`wp_posts`) | **入らない** |
| カスタマイザーで色やロゴを設定 | データベース (`wp_options`) | **入らない** |
| 管理画面「メディア」から追加した画像 | `wp-content/uploads/` ＋ データベース | **入らない** |
| フォントライブラリで追加したフォント | `wp-content/uploads/fonts/` ＋ データベース | **入らない** |

つまり、**テーマ zip をアップロードしただけだと、見た目がスカスカの状態になります**。
画像が消え、文言が初期状態に戻り、フォントが外れます。

今回は「どこをどう変更したか混在していて分からない」とのことなので、
**サイト全体（ファイル＋データベース）を丸ごと移す方針**で進めます。これが最も確実です。

### Studio のデータベースは SQLite です

Studio はローカル用に **SQLite** を使っています。一方、エックスサーバー等の本番は
**MySQL / MariaDB** です。形式が違うため、**データベースのファイルをそのまま
FTP でアップロードしても動きません。**

この変換を自動でやってくれるのが、後述の All-in-One WP Migration プラグインです。

### エックスサーバーの「WordPress簡単移行」は使えません

エックスサーバーには「WordPress簡単移行」機能がありますが、これは
**インターネット上に公開されている URL** から取り込む仕組みです。
Studio のサイトは自分の PC の中だけで動いていて外から見えないため、この機能は使えません。

## 1. フェーズ0 — 現状を調べる

まず、何がどこにあるのかをはっきりさせます。

```bash
cd <このリポジトリ>/rexel/scripts
chmod +x *.sh
./inspect-studio-site.sh ~/Studio/REXEL
```

`~/Studio/REXEL` は実際のフォルダに読み替えてください。
場所が分からない場合は、Studio アプリでサイトを開き
**「サイトフォルダを開く」**（Open site folder）から確認できます。
`wp-content` と `wp-config.php` が直下にあるフォルダが正解です。

レポートをファイルに残しておくと後で参照しやすいです。

```bash
./inspect-studio-site.sh ~/Studio/REXEL > ~/Desktop/rexel-調査結果.txt
```

### レポートの読み方

**「4. データベース側の見た目の変更」の件数を必ず見てください。**

- `wp_template` / `wp_template_part` / `wp_global_styles` が **0 件** →
  サイトエディターは使っていない。テーマ zip 中心の移管でも足りる可能性がある（ルートC）。
- **1 件でもある** → サイトエディターでの編集がデータベースに入っている。
  **ルートA（サイト丸ごと移行）が必須**です。

また「8. 容量」の `wp-content 合計` をメモしてください。移行方法の選択に使います。

---

## 2. フェーズ1 — バックアップを取る

移管作業の前に、必ず現状を保存します。

```bash
./backup-rexel.sh ~/Studio/REXEL
```

デスクトップに `rexel-backup-YYYYMMDD-HHMMSS` フォルダができます。中身は以下の通りです。

```
01_テーマzip/       本番の「テーマのアップロード」にそのまま入れられる zip
02_メディア/        uploads 一式（画像・フォント）
03_データベース/    文言・ページ内容・サイトエディターの変更・フォント設定
04_サイト全体/      wp-content 丸ごと（保険）
05_レポート/        どのファイルをいつ触ったかの一覧とハッシュ
はじめにお読みください.txt
```

> **注意**: `04_サイト全体/wp-config.php.参考` にはデータベース接続情報が入っています。
> 本番サーバーにアップロードしないでください。また、人に渡したり
> GitHub 等に公開したりしないでください。

このフォルダは移管が完全に終わるまで消さないでください。
可能なら外付けドライブやクラウドストレージにもコピーしておくと安全です。

## 3. フェーズ2 — 本番へ移管する

3 つのルートがあります。フェーズ0 のレポートを見て選んでください。

| | ルートA | ルートB | ルートC |
|---|---|---|---|
| 内容 | サイト丸ごと移行 | 手動移行 | テーマだけ移行 |
| おすすめ度 | **推奨** | 容量超過時 | 限定的 |
| 条件 | `wp-content` が数百MB以内 | 容量が大きい | DB側の変更が0件のとき |
| 難易度 | 低 | 高 | 低 |

---

### ルートA — All-in-One WP Migration（推奨）

SQLite → MySQL の変換も、URL の置換も、プラグインが自動でやってくれます。

#### A-1. 本番サイトを先にバックアップする

**本番にすでに何かサイトが入っている場合、この作業で全部上書きされます。**
エックスサーバーの管理画面（サーバーパネル）には自動バックアップ機能があります。
念のため手動でもバックアップを取ってから進めてください。

本番がまっさらな新規 WordPress なら、この手順は飛ばして構いません。

#### A-2. Studio 側でエクスポート

1. Studio で REXEL のサイトを起動し、WordPress の管理画面を開く
2. 「プラグイン → 新規追加」で **All-in-One WP Migration** を検索してインストール、有効化
3. 左メニューの「All-in-One WP Migration → エクスポート」を開く
4. 「エクスポート先」で **ファイル** を選ぶ
5. しばらく待つとダウンロードボタンが出るので、`.wpress` ファイルを保存する

> `.wpress` ファイルもバックアップフォルダに一緒に入れておくことをおすすめします。

#### A-3. 本番側でインポート

1. 本番の WordPress 管理画面にログイン
2. 同じく **All-in-One WP Migration** をインストール、有効化
3. 「All-in-One WP Migration → インポート」を開く
4. 先ほどの `.wpress` ファイルをドラッグ＆ドロップ
5. 「サイトを上書きします」という確認が出るので、内容を読んで進める

#### A-4. インポート直後の必須作業

**ログイン情報が Studio 側のものに置き換わります。** 本番のユーザー名・パスワードは
Studio で使っていたものに変わるため、一度ログアウトして
**Studio 側の ID とパスワード**でログインし直してください。

その後、以下を必ず行います。

1. **パーマリンクの再保存**
   「設定 → パーマリンク」を開き、何も変更せず「変更を保存」を **2 回** クリック。
   これをしないとトップページ以外が 404 になります。
2. **SQLite 用プラグインの削除**
   「プラグイン」一覧に **SQLite Database Integration** があれば停止・削除してください。
   本番は MySQL なので不要です。残っていると不具合の原因になります。
3. **サイトアドレスの確認**
   「設定 → 一般」で、WordPress アドレスとサイトアドレスが本番のドメイン
   （`https://` 付き）になっているか確認。

#### A-5. インポート容量の上限に引っかかった場合

無料版にはインポートサイズの上限があります（環境により 40MB〜512MB 程度）。
フェーズ0 で確認した `wp-content 合計` がこれを超えている場合、
「最大アップロードサイズを超えています」というエラーが出ます。

対処は次のいずれかです。

- エックスサーバーの「php.ini設定」で `upload_max_filesize` と `post_max_size` を
  512M 程度に引き上げる（サーバーパネルから変更できます）
- ルートB に切り替える

---

### ルートB — 手動移行（容量が大きい場合）

ファイルと中身を分けて運びます。

#### B-1. ファイル（画像・フォント・テーマ）を FTP で送る

バックアップフォルダの中身を、FTP ソフト（FileZilla や
エックスサーバーのファイルマネージャ）で本番にアップロードします。

| 送るもの | 本番の置き場所 |
|---|---|
| `01_テーマzip/` の中身を展開したフォルダ | `wp-content/themes/` |
| `02_メディア/uploads.zip` を展開した中身 | `wp-content/uploads/` に統合 |

テーマについては、FTP を使わず管理画面から入れる方が簡単です。
「外観 → テーマ → 新規追加 → テーマのアップロード」で `01_テーマzip/` の
zip をそのまま選べます。**子テーマの場合は親テーマを先に**アップロードしてください。

#### B-2. 中身（文言・ページ）を運ぶ

1. Studio 側の管理画面で「ツール → エクスポート」を開く
2. 「すべてのコンテンツ」を選んでエクスポートファイル（XML）をダウンロード
3. 本番の管理画面で「ツール → インポート → WordPress」を選び、
   インポーターをインストールしてから XML を取り込む
4. 「添付ファイルをダウンロードしてインポートする」の**チェックは外す**
   （Studio はローカルなので本番から画像を取りに行けません。画像は B-1 で送済みです）

#### B-3. ルートB の限界を理解しておく

標準のエクスポート/インポートでは、**次のものは移りません**。

- カスタマイザーの設定（色、ロゴ、サイト基本情報）
- ウィジェットの配置
- サイトエディターで編集したテンプレート（環境により移らないことがあります）
- プラグインの設定

これらは本番で手作業でやり直す必要があります。
そのため、可能な限りルートA を選ぶことをおすすめします。

---

### ルートC — テーマだけ移行

フェーズ0 のレポートで `wp_template` / `wp_template_part` / `wp_global_styles` が
**すべて 0 件**で、かつ画像もフォントもテーマフォルダの中に置いてある場合のみ有効です。

1. 本番の管理画面で「外観 → テーマ → 新規追加 → テーマのアップロード」
2. `01_テーマzip/` の zip を選んでアップロード（子テーマなら親テーマを先に）
3. 「有効化」

文言やページの中身は別途 B-2 の手順で運んでください。

## 4. フェーズ3 — 移管後の確認

本番サイトを開いて、以下を上から順に確認してください。
**必ずスマートフォンでも確認してください。**

### 画像

- [ ] トップページのメインビジュアルが表示されている
- [ ] 各ページの画像が表示されている（欠けた画像アイコンになっていないか）
- [ ] ロゴ・ファビコンが出ている
- [ ] 画像が出ない場合 → ブラウザで画像を右クリック → 「画像アドレスをコピー」して
      URL を確認。`localhost` が含まれていたら URL 置換ができていません（下記トラブル参照）

### フォント

- [ ] 見出しと本文が、Studio で見ていたときと同じ書体になっている
- [ ] 明朝／ゴシックが入れ替わっていないか
- [ ] フォントが違う場合 → `wp-content/uploads/fonts/` が本番にアップロードされているか確認
- [ ] ブラウザの検証ツール（F12）→「ネットワーク」タブでフォントファイルが
      404 になっていないか確認

### 文言

- [ ] トップページのキャッチコピーが改修後のものになっている
- [ ] 各ページの見出し・本文が最新になっている
- [ ] 会社情報・連絡先などが正しい
- [ ] メニュー（ナビゲーション）の項目名とリンク先
- [ ] フッターの著作権表記

### その他

- [ ] トップページ以外のページが開ける（404 にならない）
- [ ] お問い合わせフォームが送信できる（送信先メールアドレスの設定も確認）
- [ ] `https://` で鍵マークが出る
- [ ] 「設定 → 表示設定」で「検索エンジンがサイトをインデックスしないようにする」の
      **チェックが外れている**（これが入っていると Google に載りません）

### 照合したい場合

バックアップの `05_レポート/ファイル一覧-ハッシュ.txt` に、移管前のテーマファイルの
ハッシュ値が入っています。本番から同じテーマフォルダを FTP でダウンロードして
ハッシュを取り直せば、ファイルが正しく届いたか厳密に確認できます。

## 5. よくあるトラブル

### 画像の URL に `localhost` が残っている

インポート時の URL 置換が効いていません。
All-in-One WP Migration の「検索と置換」機能、または
**Better Search Replace** プラグインで置換します。

- 検索する文字列: `http://localhost:8881`（フェーズ0 レポートの「サイトURL」の値）
- 置換後の文字列: `https://本番のドメイン`
- 「ドライラン」で件数を確認してから、チェックを外して実行

### トップページ以外がすべて 404

パーマリンクの再保存をしていません。
「設定 → パーマリンク」で「変更を保存」を 2 回押してください。

それでも直らない場合、`.htaccess` の書き込み権限を確認してください。

### 管理画面にログインできない

インポートによってログイン情報が Studio 側のものに置き換わっています。
**Studio で使っていた** ユーザー名とパスワードでログインしてください。

どちらも分からない場合は、エックスサーバーの phpMyAdmin から
`wp_users` テーブルのパスワードを `MD5` 関数でリセットできます。

### 「データベース接続確立エラー」

`wp-config.php` を Studio のもので上書きしてしまった可能性が高いです。
本番の `wp-config.php` は本番サーバーのデータベース情報が書かれているため、
**Studio のものに置き換えてはいけません**。
エックスサーバーのバックアップから復元してください。

### 表示が崩れる・一部のスタイルが効かない

1. ブラウザのキャッシュを消す（スーパーリロード: Ctrl+F5 / Cmd+Shift+R）
2. キャッシュ系プラグインが入っていれば、キャッシュを削除
3. エックスサーバーの「サーバーパネル → サーバーキャッシュ設定」でキャッシュをクリア

### フォントだけ反映されない

WordPress のフォントライブラリを使っている場合、
**ファイル（`uploads/fonts/`）とデータベースの両方**が揃って初めて反映されます。
片方だけだと外れます。ルートA で移行し直すのが確実です。

## 6. 補足

このガイドは、フェーズ0 の調査結果を前提に手順を組んでいます。
Studio のバージョンによってメニュー名や内部構成が異なる場合があるため、
画面の表記が違ったときは、まず `inspect-studio-site.sh` のレポートを
確認してから判断してください。

作業中に迷ったら、レポートとエラーメッセージを手元に用意した上で
Claude Code に相談すると、状況に合わせた次の一手を出せます。
